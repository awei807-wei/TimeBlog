# ADR-008：公开副本与私有原件分层

- 状态：已接受
- 决策：规范原始媒体保存在受保护卷，公开副本由存储适配层管理；私人媒体不生成匿名可访问 URL。
- 原因：导出、回收站和权限边界不能依赖第三方图床的私有能力。
- 后果：上传和导出需维护媒体元数据、校验和、引用计数和副本状态；媒体完成后才允许正文引用。
- 安全补充：外部 `custom_public` 的端点和启用意图可入库，Token 使用独立配置密钥加密且只允许覆盖/保持/清除；启用意图保存为 `credentials_unverified`，只有无副作用验证达到 `verified`/`scope_limited` 且确认稳定公开 URL 后才允许异步发布。Token 未通过门禁时不得发布或删除远端文件。

## 2026-09-29：写作附件与图床优先

- 管理写作页与首页快速写作弹窗共用附件按钮；按 UA（含桌面 UA 的 iPadOS）识别移动设备，提供“拍摄照片”和“选择文件”；桌面直接打开系统文件选择。
- 移除独立上传区；正文接收文件粘贴与拖放。拖入时高亮，松手后自动上传；浏览器的受保护拖拽数据模式不允许仅悬停就读取文件。
- 复用原有上传队列、CSRF、断点续传和 media:// 引用，不将图床 Token 暴露给浏览器。
- 图床配置启用且验证通过时，支持格式且不超过 20 MiB 的公开图片自动排入外部发布任务；私人图片、其他附件、不支持的图片格式或超限图片仍保存在本地。API 与 Worker 共用发布资格判断。
- 外部发布成功的公开图片 GET 优先临时跳转到图床；HEAD、Range 与 ?local=1 仍读取本地原件。发布未完成或失败时不影响本地读取。图床图片加载失败时，正文预览和文章显示仅回退本地一次；不依赖外部 CORS 凭据支持。
- 规范原件、媒体权限、导出和草稿占位符继续由站点管理。真实相机兼容性需在目标手机验证；自动测试不调用真实图床上传接口。
